# mapExit 게임 설계

이 문서는 사용자와 결정한 게임 규칙과 구현 기본안을 기록한다. 수치와 구현 기본안은 플레이 테스트 후 조정할 수 있다.

## 1. 확정된 게임 개요

- 서버 없이 기기 안에서만 플레이하는 안드로이드 앱.
- 도트 그래픽, 세로 화면 전용.
- 게임 진행 조작은 버튼 두 개.
- 지상에서 출발해 지하로 내려가고, 50층을 클리어하면 엔딩 후 장비 하나를 이어받아 지상에서 새 회차를 시작한다.
- 한 층의 목표 플레이 시간은 약 5분. 처음 제안한 한 판 10분은 층별 약 5분과 선택적 귀환 구조로 대체한다.
- 5분은 평균 분량 목표이며 강제로 기다리는 시간이나 제한 시간이 아니다.
- 층 클리어 시 다음 층으로 진행할지 지상으로 귀환할지 선택한다.
- 50층 클리어 시에는 51층 진행 대신 엔딩과 회차 전환으로 연결한다. 스테이터스와 소지·보관 골드를 초기화하고, 장비 하나만 다음 회차로 이어받는다.

## 2. 화면과 입력

화면은 메인 화면, 미니맵, 버튼 두 개, 캐릭터 스테이터스의 네 구역으로 나눈다.

| 영역 | 내용 |
|---|---|
| 메인 화면 | 탐험 중에는 1인칭, 몬스터와 조우하면 3인칭 전투 화면 |
| 미니맵 | 탐험 중인 층, 현재 위치와 방향 |
| 버튼 영역 | 두 버튼과 현재 선택 중인 행동 |
| 스테이터스 | 캐릭터의 일곱 능력치 및 변화 |

탐험 중 통로는 자동으로 이동하고 갈림길에서 방향을 선택한다.
전투는 타이밍 입력이 아닌 행동 선택 방식이다.
성장은 경험치로 레벨업한 뒤 올릴 능력치를 직접 선택한다.

다음은 초기 구현 기본안이다.

- 왼쪽 위 메인 화면, 오른쪽 위 미니맵, 왼쪽 아래 조작, 오른쪽 아래 스테이터스로 배치한다.
- 일반 탐험과 메뉴에서는 A 버튼은 선택 항목 변경, B 버튼은 실행/확정으로 통일한다. 함정 미니게임에서는 안내에 맞춰 A/B 버튼을 직접 누르거나 뗀다.
- 이동, 전투, 장비, 상점, 미션, 골드 보관소, 성장 배분을 모두 두 버튼으로 이용한다.
- 메뉴에는 돌아가기 항목을 포함한다.
- 자동 이동은 갈림길, 진행 불가능한 지점, 상호작용 대상, 전투 조우, 층 출구에서 멈춘다.
- 미니맵은 탐험한 공간을 밝힌다. 전투 중에는 조우한 위치를 유지한다.
- 도트 이미지는 정수 배율 확대와 보간 없는 표시를 우선한다.

## 3. 던전 구성

같은 층에 다시 도전해도 지형과 몬스터·시설 배치를 새로 생성한다.

| 배치 요소 | 역할 |
|---|---|
| 몬스터 | 조우하면 전투 진입 |
| 아이템 상자 | 아이템 획득 |
| 회복 장소 | 체력 회복 |
| 상인 | 아이템 거래 |
| 미션 NPC | 미션 수락, 진행 확인, 완료 보상 |
| 다음 층으로 내려가는 문 | 층 종료와 다음 층/지상 선택 |
| 함정 | 다섯 종류의 A/B 미니게임. 회피 실패 시 피해 |

- 층별 배치 수, 적 종류, 보상, 회복량, 함정 효과는 데이터로 관리한다.
- 매 층 모든 시설을 반드시 배치할지, 일부 시설을 확률로 배치할지는 밸런스 기본안에서 정한다.
- 생성기는 출발점에서 출구까지의 이동 가능성을 검증한다.
- 출구, 보스, 미션 목표 등 필수 대상은 접근 가능한 공간에 배치한다.
- 자동 이동의 중단과 갈림길 판단은 맵 데이터에 근거한다.
- 같은 탐험 안에서 사용한 상자, 회복 장소, 함정, 처치한 적의 상태는 보존하는 것을 기본안으로 한다.
- 일반 층은 출구 도달로 클리어, 보스 층은 보스 처치 후 출구 이용을 기본안으로 한다.

### 3.1. 함정 미니게임 다섯 종류

함정 조우 시 자동 이동을 정지하고 메인 화면에 짧은 미니게임을 표시한다. 네 구역 화면과 A/B 두 버튼을 유지한다. 전투의 행동 선택 입력과 구분해 함정에서는 버튼의 직접 입력을 판정한다.

| 타입 | 진행 방식 | 성공 조건 |
|---|---|---|
| 순간 입력 | 짧게 제시된 A/B 지시를 제한 시간 안에 입력 | 제시된 입력을 제한 시간 안에 완료 |
| 타이밍 바 | 표시된 바 위에서 움직이는 표시기를 버튼으로 멈춤 | 목표 구간 안에서 정지 |
| 연타 | 지정된 버튼을 제한 시간 안에 여러 번 누름 | 목표 횟수 이상 입력 |
| 패턴 기억 | A/B 패턴을 잠시 보여준 뒤 숨기고 입력 시작 | 같은 순서를 정확히 재현 |
| 누르고 떼기 | 지정 버튼을 누르고 있다가 신호가 바뀌면 뗌 | 신호가 바뀐 후 허용 시간 안에 손을 뗌 |

첫 네 종류는 사용자 요청이다. 다섯 번째는 추가 기획안으로 채택한다.

타입별 초기 상세 규칙:

1. 순간 입력: 요청의 '짧은 시간 내에 A,B 누르기'는 A→B 또는 B→A 같은 짧은 지시를 표시하고 그 순서대로 입력하는 것으로 해석한다. 지시는 입력 중에도 보이므로 패턴 기억과 구분된다. 동시 누르기를 요구하지 않는다. 잘못된 버튼이나 제한 시간 초과는 실패로 처리한다.
2. 타이밍 바: 목표 구간과 이동 표시기를 보여준다. 안내에 제시된 버튼을 한 번 누른 시점의 위치로 판정한다. 전체 제한 시간 안에 입력하지 않거나 목표 구간 밖에서 누르면 실패한다. 처음에는 일정 속도의 단방향 또는 왕복 움직임을 설정으로 선택한다.
3. 연타: 매 함정에 A 또는 B 중 목표 버튼을 지정한다. 한 번의 누름과 떼기를 한 입력으로 세고, 목표 횟수를 채우면 즉시 성공한다. 다른 버튼은 횟수에 포함하지 않고, 제한 시간 안에 목표를 채우지 못하면 실패한다.
4. 패턴 기억: 제시 단계에는 패턴을 보여주고 입력을 받지 않는다. 패턴이 사라진 뒤 입력 단계로 전환해 전체 제한 시간 안에 같은 순서를 입력하게 한다. 오입력 또는 시간 초과는 실패한다.
5. 누르고 떼기: A 또는 B 중 지정된 버튼을 눌러 유지한다. 누르기 시작하는 시간에도 제한을 두고, 버튼을 유지하는 동안 '유지' 신호가 '놓기' 신호로 바뀐다. 너무 일찍 떼거나 신호 후 허용 시간을 넘겨 떼면 실패한다. 신호가 바뀌는 시점은 설정 범위 안에서 난수로 정하되 미리 확정해 재현할 수 있게 한다.

공통 진행과 판정 기본안:

- 안내/준비 → 진행 → 성공 또는 실패 → 탐험 복귀로 상태를 분리한다.
- 안내에 타입, 사용할 버튼, 성공 조건을 표시하고 준비 시간을 제공한다.
- 함정으로 진입하게 한 입력이나 이미 누르고 있던 버튼은 함정 입력으로 넘기지 않는다. 버튼을 모두 뗀 뒤 준비를 시작한다.
- 함정이 진행 중일 때는 일반 메뉴 선택·확정과 이동 입력을 함께 처리하지 않는다.
- 성공하면 함정 피해 없이 통과한다. 실패하면 설정한 HP 피해를 한 번 적용한다.
- 피해 적용 직후 HP가 0이면 기존 사망 규칙으로 지상에서 부활시킨다.
- 한 탐험에서 해결한 함정은 결과를 기록해 같은 위치에서 중복 발동하지 않게 한다.
- 앱이 백그라운드로 가면 판정 시간을 정지한다. 재개 시 동일한 패턴·진행량·남은 시간을 복원하고, 누르고 떼기 타입은 재개 안내 후 지정 버튼을 다시 누른 상태에서 남은 진행을 이어간다.
- 판정은 화면 프레임 수가 아닌 주입 가능한 게임 시간과 입력 시각으로 계산한다.
- A/B 버튼의 누름과 뗌을 따로 기록하고, 길게 누르기의 자동 반복은 연타 횟수로 세지 않는다.
- 연타·순간 입력·기억 입력에서 손가락 하나를 계속 누른 상태로 입력을 중복 생성하지 않는다.

밸런스 설정:

- 공통: 등장 비중, 안내 시간, 준비 시간, 실패 피해량.
- 순간 입력: 지시 길이, 입력 제한 시간.
- 타이밍 바: 전체 제한 시간, 이동 속도, 목표 구간 위치·폭, 이동 방식.
- 연타: 목표 버튼, 제한 시간, 요구 횟수.
- 패턴 기억: 패턴 길이, 제시 시간, 입력 제한 시간.
- 누르고 떼기: 목표 버튼, 누르기 시작 제한 시간, 신호 전환 시간 범위, 신호 후 허용 시간.
- 층별 난이도는 위 설정으로 조정하며 각 값에 상한·하한을 두어 50층까지 조작 가능한 범위를 유지한다.
- 타입과 패턴, 목표 구간, 신호 전환 시점은 난수 시드와 함께 재현 가능하게 한다.

## 4. 전투

몬스터 조우 시 탐험을 멈추고 플레이어와 몬스터가 함께 보이는 3인칭 도트 전투 화면으로 전환한다.

전투는 아래 두 단계를 번갈아 반복한다.

1. 플레이어 공격 / 몬스터 방어: 플레이어가 행동을 선택하고 결과를 계산한다.
2. 몬스터 공격 / 플레이어 방어: 플레이어가 방어 행동을 선택하고 결과를 계산한다.

- 전투 입력을 기다리는 동안에는 다음 단계로 진행하지 않는다.
- 각 행동 결과 처리 직후 사망 여부를 판정한다.
- 몬스터가 사망했다면 몬스터의 반격 없이 승리 처리한다.
- 플레이어가 사망했다면 즉시 사망 처리한다.
- 강공격은 일반 공격보다 강한 대신 명중 확률이 낮아 빗나갈 수 있다.
- 도주 시도는 플레이어의 공격 차례를 사용한다.
- 도주에 실패하면 몬스터 공격 / 플레이어 방어 단계로 넘어간다.
- 도주 성공률, 일반 공격과 강공격의 수치, 방어·회피 효과는 밸런스 설정으로 관리한다.
- 방어는 피해 감소, 회피는 확률적으로 피해 회피를 시도하는 것을 초기 기본안으로 한다.
- 전투 종료 후에는 1인칭 탐험으로 복귀한다.
- 도주 후 복귀 위치와 재조우 방지 방식, 소모품 사용의 턴 소모 방식은 구현 기본안에 명시하고 검증한다.
- 보스전 도주에 별도 제한을 추가한다면 사용자에게 확인한다. 현재는 공통 도주 규칙을 적용한다.

## 5. 캐릭터 성장과 장비

| 스테이터스 | 초기 역할 정의 |
|---|---|
| 체력 | 현재 HP와 최대 HP |
| 공격력 | 공격 피해에 영향 |
| 방어력 | 받는 피해 감소 |
| 민첩 | 회피와 도주 등 관련 확률에 영향 |
| 치명타 확률 | 치명타 발생 확률 |
| 치명타 공격력 | 치명타 피해 배율 |
| 행운 | 아이템 획득과 희귀 보상 등에 영향 |

확정된 성장 방식:

- 경험치 획득으로 레벨업한다.
- 레벨업 시 사용자가 올릴 능력치를 직접 선택한다.
- 캐릭터의 성장한 스테이터스는 일반 사망 후 유지한다. 50층 클리어 후 회차를 전환할 때는 초기화한다.
- 장비는 무기, 머리, 몸, 발 등 부위별 슬롯을 사용한다.

초기 구현 기본안:

- 캐릭터 자체의 능력치와 장비 보정을 따로 계산한다.
- 사망 시 장비를 잃으면 그 장비의 능력치 보정도 제거한다.
- 민첩에 따라 한쪽이 연속 행동하지 않으며 공격·방어 교대 순서를 유지한다.
- 장비 슬롯의 정확한 목록, 성장 포인트 수, 능력치 상승량, 확률 상한은 설정으로 관리한다.
- 무장하지 않은 상태에서도 기본 공격을 할 수 있게 해 사망 후 다시 시작할 수 있게 한다.

## 6. 귀환, 사망, 보관소

| 대상 | 정상 귀환 | 일반 사망 | 50층 클리어 후 새 회차 |
|---|---|---|---|
| 캐릭터 성장 수치 | 유지 | 유지 | 초기화 |
| 소지 아이템 | 유지 | 전부 소실 | 계승 장비 하나를 제외하고 소실 |
| 착용 장비 | 유지 | 전부 소실 | 계승 장비 하나를 제외하고 소실 |
| 소지 골드 | 유지 | 전부 소실 | 0으로 초기화 |
| 지상 보관 골드 | 유지 | 유지 | 0으로 초기화 |
| 활성화한 이동 장치 | 유지 | 유지 | 유지/초기화 여부 확인 필요 |
| 진행 중인 미션 | 종료 | 종료 | 종료 |

- 사망하면 지상에서 부활한다.
- 지상에는 골드만 보관할 수 있다. 장비와 소모품 등 아이템은 항상 소지한다.
- 보관과 인출은 지상 메뉴에서 처리하는 것을 기본안으로 한다.
- 정상 귀환 시 소지 골드를 자동 보관할지 여부는 기본안에서 명시한다. 자동 보관은 아직 확정 규칙이 아니다.
- 부활 시 현재 HP를 회복하는 것을 기본안으로 한다.
- 경험치 잔량과 미사용 성장 포인트는 일반 사망 후 보존하는 것을 기본안으로 한다. 회차 전환 시에는 레벨과 함께 초기화해 성장 초기화를 우회하지 않게 한다.

## 7. 보스와 이동 장치

- 10, 20, 30, 40, 50층에 보스가 등장한다.
- 해당 층에 도착하는 것만으로는 이동 장치가 활성화되지 않는다.
- 해당 층의 보스를 처치하면 그 층의 이동 장치를 활성화한다. 같은 회차의 귀환·사망 후에도 해금 상태를 보존한다.
- 지상에서 활성화한 장치로 해당 층까지 바로 내려갈 수 있다.
- 귀환하거나 사망해도 활성화 상태는 유지한다.
- 같은 탐험에서 보스 처치 보상과 장치 활성화가 중복 처리되지 않게 한다.
- 50층 보스와 클리어 처리 후 엔딩과 장비 계승·회차 전환을 진행하며, 51층은 생성하지 않는다.
- 새 탐험에서 활성화된 보스 층을 재방문할 때 보스의 재등장과 보상을 어떻게 처리할지는 구현 기본안에 명시한다.
- 엔딩 후에는 아래 장비 계승 규칙에 따라 지상에서 새 회차를 시작한다. 회차 전환 시 이동 장치도 초기화할지는 사용자에게 확인할 남은 항목이다.

### 7.1. 50층 클리어 후 장비 계승과 새 회차

확정된 규칙:

- 50층을 클리어하면 스테이터스와 돈을 초기화하고 지상에서 다시 부활해 새 회차를 시작한다.
- 소지 골드와 지상에 보관한 골드를 모두 0으로 초기화한다.
- 장비 하나만 다음 회차로 이어받을 수 있다. 여러 회차를 클리어해도 계승 개수는 늘어나지 않는다.
- 첫 클리어에서는 보유 장비 중 이어받을 한 개를 선택한다.
- 다음 50층 클리어 시 직전 회차에서 이어받은 그 장비를 착용 중이면, 선택 화면 없이 자동으로 같은 장비 하나를 이어받는다.
- 자동 계승은 같은 종류의 다른 장비가 아니라 직전 계승 장비 개체를 기준으로 한다.

요청을 구체화한 구현 기본안:

- 장비 선택 후보에는 착용 장비와 인벤토리에 보유한 장비를 모두 포함한다. 소모품은 선택할 수 없다.
- 직전 계승 장비를 착용하지 않았거나 매각·소실했다면 자동 계승하지 않고 현재 보유 장비 중 한 개를 다시 선택한다. 직전 장비를 인벤토리에만 가지고 있는 경우에는 수동 선택 후보로는 남는다.
- 계승하지 않은 장비와 소모품 등 나머지 아이템은 모두 없앤다.
- 이어받을 장비가 하나도 없으면 장비 없이 새 회차를 시작할 수 있다.
- 장비 개체의 속성은 그대로 보존한다. 캐릭터 기본 스테이터스는 시작 값으로 초기화하고, 그 장비를 착용하면 장비 보정은 정상 적용한다.
- 레벨, 경험치, 배분한 성장 수치와 미사용 성장 포인트는 시작 상태로 초기화하고 현재 HP는 초기 최대 HP에 맞춘다.
- 진행 중인 미션과 현재 던전·전투·함정 상태를 종료하고 지상으로 이동한다.
- 일반 사망은 기존 규칙을 적용한다. 계승 장비에도 별도 사망 보호 기능을 추가하지 않으며, 소실된 계승 장비를 클리어 시 임의 복원하지 않는다.
- A로 계승 후보 변경, B로 선택 확정한다. 자동 계승일 때는 결과를 표시하고 진행한다.
- 장비 선택을 완료하기 전에 초기화를 확정하지 않는다. 선택 대기 상태와 완료 상태를 저장하고, 회차 전환은 하나의 저장 작업으로 반영해 중복 계승·소실을 방지한다.

남은 확인 항목:

- 새 회차에서 이동 장치를 모두 다시 해금할지, 이전 회차의 해금 상태를 유지할지 결정해야 한다.
- 이 항목은 일반 사망·귀환 시 이동 장치가 유지된다는 기존 규칙과 별개다.

## 8. 미션

- NPC로부터 미션을 받고 여러 층에 걸쳐 수행할 수 있다.
- 미션은 현재 탐험 안에서 유효하며 귀환 또는 사망 시 진행 중인 미션이 종료된다.
- 처치, 수집, 특정 층 도달 등 구체적인 미션 종류와 보상은 데이터로 정의한다.
- 랜덤 맵에서도 수행 가능한 목표만 생성해야 한다.
- 미션 목표의 배치, 완료 조건, 보상 수령 여부를 분리해 보상 중복 수령을 방지한다.
- 귀환 시 종료되는 미션을 완료하고 NPC에게 보고하는 동선은 생성 단계에서 검증한다.

## 9. 구현 구조 기본안

- 안드로이드 앱: Kotlin + Jetpack Compose.
- 게임 영역: Canvas로 도트 이미지와 도형을 그린다.
- 게임 규칙: 안드로이드 의존성이 없는 순수 Kotlin 모듈.
- 설정: 맵 생성, 몬스터, 아이템, 미션, 성장과 전투 수치를 별도 데이터로 관리.
- 저장: 기기 내부 저장. 회차 안에서 귀환·사망 후 유지할 성장·보관 골드·장치 데이터, 현재 탐험 데이터, 회차 번호·계승 장비 식별 데이터를 구분한다. 일반 사망 시 보존할 데이터도 회차 전환 때는 정해진 규칙대로 초기화한다.
- 저장 형식에 버전을 두고 불러오기와 향후 변경을 검증.
- 앱이 백그라운드로 가면 정지하고, 재개 시 현재 탐험 상태에서 이어가는 것을 기본안으로 한다.
- 게임 규칙에 사용하는 난수와 시간은 외부에서 주입할 수 있게 한다.
- 같은 규칙 버전, 난수 시드, 초기 상태, 입력 기록으로 같은 결과를 재현한다.
- 화면 갱신 속도와 게임 진행 시간을 분리한다.

권장 모듈과 책임:

| 모듈/영역 | 책임 |
|---|---|
| core | 맵, 탐험, 전투, 함정 판정, 성장, 미션, 귀환, 사망 규칙 |
| app | 화면, 터치 입력, 생명주기, 소리, 내부 저장 연결 |
| 콘텐츠 데이터 | 몬스터, 아이템, 층별 배치, 미션, 밸런스 |
| 개발용 기능 | 시드 고정, 배속, 상황 바로 시작, 입력 재생 |

개발용 기능은 실제 배포 플레이 화면의 두 버튼 제약과 구분한다.

## 10. 우선 구현 및 검증 순서

1. 고정된 작은 테스트 층과 네 구역 화면, 두 버튼 조작.
2. 통로 자동 이동, 갈림길 선택, 일곱 가지 맵 요소와 상호작용. 다섯 함정은 각각 바로 시작할 수 있게 한다.
3. 1인칭/3인칭 전환과 공격·방어 교대, 강공격, 도주, 승패.
4. 성장 배분, 부위별 장비, 골드 보관, 사망·귀환과 저장.
5. 랜덤 층 생성, 여러 층 미션, 보스, 이동 장치.
6. 데이터로 50층 진행, 엔딩, 장비 계승과 새 회차 시작을 연결하고 층별 분량 조절.
7. 실제 안드로이드 기기에서 버튼 크기, 화면 가독성, 자동 이동 속도와 약 5분의 분량 확인.

핵심 자동 검증 대상:

- 같은 시드와 입력으로 같은 상태에 도달하는가.
- 생성한 맵의 필수 경로와 미션 목표에 접근 가능한가.
- 자동 이동이 갈림길, 조우, 상호작용, 출구에서 멈추는가.
- 몬스터 처치 후 반격이 발생하지 않는가.
- 도주 실패 후 방어 선택을 포함하는 몬스터 공격 단계로 진행하는가.
- 사망 시 소지품·착용 장비·소지 골드를 잃고 성장·보관 골드·장치는 유지하는가.
- 귀환 또는 사망으로 진행 중인 미션이 종료되는가.
- 보스 처치 전에는 장치가 활성화되지 않는가.
- 50층 클리어 후 51층 대신 엔딩과 장비 계승·새 회차로 진행하는가.
- 회차 전환 시 성장 수치·레벨·경험치·미사용 포인트와 소지·보관 골드가 모두 초기화되는가.
- 첫 클리어에서는 보유 장비 중 하나를 선택하고, 이후에는 직전 계승 장비를 착용 중일 때만 같은 개체를 자동 선택하는가.
- 직전 계승 장비가 인벤토리에만 있거나 매각·소실되었다면 자동 계승하지 않고 선택 단계로 가는가.
- 장비는 항상 최대 한 개만 계승하고, 나머지 장비와 소모품은 사라지는가.
- 일반 사망 시 계승 장비도 기존 장비 손실 규칙에 따라 소실되는가.
- 계승 장비가 없어도 새 회차를 시작할 수 있고, 회차 전환 도중 저장·재개 시 장비 복제나 중복 초기화가 발생하지 않는가.
- 저장과 불러오기 후 인벤토리, 전투 단계, 함정 단계·남은 시간·진행량, 난수 상태, 미션, 장치가 일치하는가.
- 다섯 함정 각각에서 성공·오입력·미입력·시간 초과가 의도대로 판정되는가.
- 타이밍 구간과 제한 시간의 경계에서 판정이 프레임 속도에 따라 달라지지 않는가.
- 연타 횟수가 버튼을 누른 채 유지하거나 자동 반복되는 이벤트로 증가하지 않는가.
- 기억 패턴의 제시 단계에서 입력이 누적되거나 다음 입력 단계로 넘어가지 않는가.
- 누르고 떼기에서 조기 해제·정상 해제·늦은 해제와 일시정지 후 재개가 구분되는가.
- 함정 진입 입력이 미니게임 입력으로 넘어가지 않고, 피해와 사망 처리가 한 번만 발생하는가.

## 11. 수치 조정과 추가 확인 기준

명중률, 강공격 배율, 회피율, 도주율, 경험치, 성장량, 보상 가격, 회복량, 함정 피해·제한 시간·목표 횟수·패턴 길이·타이밍 구간, 맵 크기, 시설 개수는 초깃값을 정하고 테스트로 조정한다.

기본안에서 세부 규칙을 정할 때에는 문서에 구분해 적는다. 확정된 사망 손실 범위, 회차 내 성장 유지와 회차 전환 초기화, 장비 계승, 장치 해금 조건, 버튼 수, 화면 방향, 전투 진행 방식처럼 플레이 구조를 바꾸는 변경은 사용자에게 확인한다.

현재 단계는 기획 문서 작성이다. 이 문서 자체가 앱 구현이나 APK 빌드 완료를 의미하지 않는다.
