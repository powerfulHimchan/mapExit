# 첫 플레이 및 수정 가이드

## 설치와 조작

Android 8.0(API 26) 이상 기기에서 debug APK를 설치한다. 네트워크 연결이나 계정이 필요 없다.

- A: 선택 항목을 다음으로 이동.
- B: 선택한 행동 실행.
- 함정에서는 화면 지시에 맞춰 A/B를 직접 누르거나 뗀다.

지상에서 1층 탐험을 선택하면 출발한다. 통로는 자동으로 이동하고 갈림길·시설·전투·함정에서 멈춘다. 이동 중 B를 누르면 멈출 수 있다.

전투는 공격 행동 선택, 몬스터 공격에 대한 방어·회피 선택을 번갈아 진행한다. 강공격은 명중률이 낮고, 회복약도 공격 차례를 사용한다. 도주에 실패하면 방어 차례로 넘어간다.

층 출구에서 다음 층 진행 또는 지상 귀환을 고른다. 10층마다 출구의 보스를 처치해야 이동 장치가 활성화된다. 지상에서 장비 교체·성장 배분·골드 보관을 할 수 있다.

일반 사망 시 아이템·착용 장비·소지 골드를 잃고 성장·보관 골드·장치 해금은 유지한다. 계승 장비도 일반 사망 시 소실된다.

50층 클리어 후 새 장비 한 개를 선택한다. 현재 보유한 기존 계승 장비는 모두 자동 보존한다. 성장·소지/보관 골드·장치는 초기화되고 1층부터 새 회차를 시작한다. 계승 장비는 가방에 들어가므로 필요한 장비를 직접 착용한다.

## 개발용 테스트

debug APK의 지상 메뉴에서 **개발용 테스트**를 선택한다. 화면 위의 TEST MODE 표시를 확인한다.

- 다섯 함정을 각각 바로 시작.
- 일반 전투 또는 10층 보스 시작.
- 50층 계승 화면 바로 시작.
- 모든 종류의 장비·골드·성장 포인트 지급.
- 1·10·30·50층 이동.
- 사망 처리 확인.
- 시드 20261028로 고정.

테스트 모드는 일반 저장과 분리된다. 테스트 메뉴의 **테스트 종료 · 원래 게임 복원**을 고르면 진입 전 상태로 돌아간다. 앱을 종료한 뒤 다시 실행할 때는 일반 저장으로 시작한다. 테스트 저장은 일반 진행을 덮어쓰지 않는다.

## 수정할 위치

| 수정 대상 | 파일 |
|---|---|
| 무기 능력치·방패·공격 명중률·강공격 배율·회피와 방어 공식 계수 | `balance/weapons.json` |
| 장비 등급·반지·목걸이 효과·가격 | `core/.../Equipment.kt` |
| 층 크기·몬스터/시설 배치 수 | `core/.../MapGenerator.kt` |
| 함정 제한 시간·패턴 길이·연타 횟수 | `core/.../Traps.kt` |
| 몬스터 성장·레벨업·보상·사망·계승 흐름 | `core/.../GameEngine.kt` |
| 화면 배치·도트 모양·색상 | `app/.../GameScreen.kt` |
| 저장·불러오기·앱 생명주기 | `app/.../MainActivity.kt` |

`core/...`는 `core/src/main/kotlin/com/powerfulhimchan/mapexit/core/`, `app/...`는 `app/src/main/java/com/powerfulhimchan/mapexit/` 아래를 뜻한다.

Gradle이 `balance/weapons.json`을 core 모듈의 생성 소스에 포함한다. 앱과 Python 검증 도구가 같은 무기 수치를 읽는다. JSON을 수정한 뒤 APK를 다시 빌드한다. 이미 획득한 장비에는 생성 당시 속성이 저장되므로 새 수치 비교에는 테스트용 새 장비를 지급하거나 새 테스트 층을 사용한다.

## 확인할 항목

1. 실제 기기에서 버튼 크기와 네 영역의 글자 가독성이 적절한가.
2. 함정 다섯 종류에서 성공·실패가 납득 가능한가.
3. 보통 탐험 시 한 층이 약 5분인가. 이 값은 목표이며 제한 시간이 아니다.
4. 무기별 생존과 전투 속도의 장단점이 느껴지는가.
5. 귀환을 선택할 만한 위험과 보상이 있는가.

첫 버전은 기능과 저장 흐름을 검증하는 단계다. 층당 실제 소요 시간, 1~50층의 난이도 곡선, 장비·반지·목걸이 전체 조합은 기기 플레이를 통해 추가 조정한다.

입력 로그를 파일로 내보내는 기능, 자동 입력 재생 UI와 배속 UI는 아직 제공하지 않는다. 고정 시드와 게임 상태 JSON, 순수 Kotlin 테스트를 이용해 문제를 재현한다.
