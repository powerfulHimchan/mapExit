# MapExit 0.29.0 — challenge movement and failure review

Special challenges now walk at the same 600ms-per-cell pace as ordinary dungeons. A chosen route starts immediately, follows unbranched corridors and bends, and stops at junctions, dead ends, unresolved altars/braziers, hazards and locked exits. The stable moving input token lets a stop gesture survive a cell transition. Pause/background cancels automatic walking. All actual cells still consume step budget and run the existing torch, collapse, timer and hazard rules; exit detection precedes exhaustion on the final permitted step.

Failure/give-up results retain the challenge map until acknowledged. The full map shows the exit, start, a distinct final-position marker and facing arrow, plus a textual grid coordinate and compass direction. Collapsed corridors are retained for review separately from current walls. Result state, collapse history and final pose survive save/recreation. Maps remain hidden during active play.

The cauldron and memory-stone obstacles now finish their final side step (250ms), hold the landing (to 400ms), then return smoothly to center (by 750ms) before the existing 900ms result ends. Wrong inputs and timeouts return from their actual last position. Physical blade/beam mechanics and collision windows remain unchanged.

Validation covers all seven challenge kinds, corners/junctions, interaction stops, stable stop gestures, pause/save, exact step budgets, failure pose persistence and collapsed-map history. Device tests exercise real navigation/stop buttons, normal/compact failure maps and recreation, plus final-input/landing/return/center captures for both sequence obstacles. The full Android workflow runs core tests, sprite consistency, lint, debug assembly, and instrumentation regressions before merging.
